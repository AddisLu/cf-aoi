# CCD04 沒影像、燈都亮、線也重插過 → 相機 IP 被改到 192.168.6.4

- 日期：2026-10-05　來源：實驗室故障注入（tools/triage/fault_inject.py、host_sudo_test.sh）　機台：user-IMB-M47 + spark-c16f + HPE 5945（借用機）
- 分類：camera　注入：{"mac": "00:30:53:54:e6:bd"}　已還原：是（還原後健檢：正常）

## 線上人員看到的（原話）
CCD04 沒有影像，可是交換機燈有亮、相機燈也有亮，線也重插過了。

## 證據：一鍵健檢結論
## 結論：❌ 1 項異常、⚠️ 0 項注意、✅ 6 項正常

1. ❌ **[相機] CCD04 的 IP 被改成 192.168.6.4（不在相機網段 192.168.5.x）→ Grab 連不到**
   - 可能原因：有人用工具改了相機 IP（暫時或永久）
   - 請這樣做：① CCD04 斷電 10 秒再上電（暫時改的 IP 會回到設定值）② 仍不對 → 相機工具「裝置設定」寫入 CCD04（IP 自動 = 192.168.5.4）（線上人員可先做）

（完整報告：`docs/troubleshooting/experiments/20261005_round2/cam_ip_changed.md`）

## 根因
相機 IP 被工具改到相機網段以外（ForceIP 暫時改；現場也可能是永久寫錯），Grab 連不到

## 處置
1. CCD04 斷電 10 秒再上電（暫時改的 IP 會回設定值）
2. 仍不對 → 相機工具「裝置設定」寫入 CCD04（IP 自動 192.168.5.4）
3. 重跑健檢

## 學到的 / 預防
「燈都亮、線也重插」= 實體層正常 → 往設定找；健檢用 GVCP 廣播掃描（跨網段也收得到）直接看出 IP

## 機況助手表現（0–2 分）
- 只給症狀（A）：**0** — 往交換機設定/相機硬體猜（錯）
- 症狀 + 健檢報告（B）：**2** — 正確指出 IP 被改，斷電重開或相機工具寫回

### 可能原因

1. **交換機埠被 shutdown 或 speed 不符** — 有人手動關閉該埠（`shutdown`），或 speed 沒設 `1000`，導致 1G 相機連不上 [3][6]
2. **交換機該埠所屬 port-group 被關閉或設定跑掉** — 不是單一埠的問題，是整組埠被改過
3. **CCD04 相機硬體故障** — 燈有亮不代表能正常取像，感光元件或通訊晶片可能異常

---

### 現場照做步驟

<details><summary>助手 B 回答原文</summary>

**結論：CCD04 的 IP 被改成了 192.168.6.4，不在相機網段 192.168.5.x 內，所以主機連不到它，收不到影像。**

---

**可能原因：**
1. 有人用工具（pylon Viewer / eBUS Player 或 `cam_provision`）**更改了 CCD04 的 IP 設定**（暫時或永久）[1]。
2. 交換機燈有亮、相機燈有亮，表示硬體連線（電、網路實體層）正常，但 IP 不對就無法通訊。

---

**現場照做步驟（線上人員可做）：**

**① CCD04 斷電重開**
- 把 CCD04 相機的電源拔掉 10 秒，再插回去。
- 如果原本的 IP 是**暫時設定**（ForceIP），斷電後就會回到原本的 `192.168.5.4`。

**② 如果重開後還是不行**
- 使用相機工具（pylon Viewer / eBUS Player）的「裝置設定」功能，寫入 CCD04 的名稱。
- 名稱寫 `CCD04` 即可，系統會自動配 IP 為 `192.168.5.4`。

---

**怎麼確認修好：**
- 再按一次「一鍵健檢」，檢查 CCD04 的 IP 是否恢復為 `192.168.5.4`。
- 或者直接在取像畫面看 CCD04 有沒有出現影像。

</details>

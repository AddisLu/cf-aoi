# 異常案例庫（機況助手的學習資料）

每個案例一個檔：`<yyyyMMdd>_<分類>_<簡述>.md`（分類：camera / switch / rdma / gpu / ip / control / other）。
機況助手（LoopEngineering）會收錄這個資料夾；**案例越多、寫得越具體，助手答得越準**。
來源可以是實驗室故障注入（`tools/triage/fault_inject.py`），也可以是現場真的發生的事——現場案例最有價值。

## 格式（照抄這段開始寫）

```markdown
# <一句話標題：症狀 → 根因>

- 日期：2026-10-05　來源：現場 / 實驗室注入　機台：CFAOI-01
- 分類：camera　嚴重度：停線 / 降級 / 提示
- 關鍵字：CCD05、沒影像、link down、線材

## 線上人員看到的（原話）
（例：Control 主畫面 CCD05 一直沒有影像，其他相機正常）

## 證據
- 一鍵健檢結論：（貼報告「結論」段）
- 相關 log：（檔名 + 關鍵幾行；log 原檔放 /srv/cfaoi/10_logs/<日期>/）

## 根因
（確認過的真正原因；不確定就寫「推測」）

## 處置
1. （現場做了什麼，誰做的）
2. 怎麼確認修好（例：重跑健檢全綠、完整度 100%）

## 學到的 / 預防
（下次怎麼更快判斷；健檢或文件要補什麼）
```

## 寫案例的小原則
- 相機講 **CCD 編號**（線材有標示、埠位會變）。
- 「線上人員看到的」用他們的原話，助手才學得到怎麼對應口語描述。
- 證據要具體（數字、燈號、哪幾行 log），不要只寫「網路異常」。

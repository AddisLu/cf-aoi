# 演算法方案目錄（2026-10-06）

> Addis：fab **不能連外網** → 所有演算法、模型、相依套件都要在機台本地；演算法要 robust，且**每一段都有多個方案讓軟體選**。
> 選法：`tools/autotune/bench_methods.py` 在乾淨影像上用**平台法**把每個組合校準到「雜訊剛好壓住」，
> 再在**人工植入缺陷**（大小 1–9 px × 對比 15–55% × 暗/亮）上比檢出率、誤判、GPU 時間 → 同樣不誤判下抓最多的勝出。
> 不需要真值、不需要外網；換產品/換光源後重跑即可。

狀態：**IP** = IP 已有（可由配方/ini 選）；**原型** = Python 已做、bench 可評，有效再搬進 IP；**規劃** = 尚未做。

## 0. 評比結果（2026-10-06，T550 IP04 整條 31 張，`bench_methods.py`）

每個組合先在乾淨整條用平台法校準到「雜訊剛好壓住」，再在 6 張 slice 植入 480 顆人工缺陷（大小 1/2/3/5/9 px × 對比 × 暗/亮）：

| 前處理 | 偵測 | 門檻 暗/亮 | 總檢出率 | 暗 對比 35/45/55% | 亮 對比 25/35/50% | 植入誤判 | GPU ms/張 |
|---|---|---|---|---|---|---|---|
| 無 | **DIV** | 0.621/1.424 | 38.1% | 28/**82/100** | 0/0/76 | 0 | **7.7** |
| 無 | DIV 投票 | 0.543/1.229 | 43.1% | 6/36/78 | **55/89/87** | 0 | 65.6 |
| 無 | SUB（T550 生產）| −36/+26 | 26.9% | 2/24/36 | 24/52/68 | 0 | 61.3 |
| FFC | DIV | 0.612/1.426 | 37.5% | 22/82/100 | 0/0/76 | 0 | 7.6 |
| FFC | DIV 投票 | 0.525/1.230 | 45.6% | 2/30/90 | 59/87/93 | 0 | 64.7 |
| FFC | SUB | −44/+32 | 29.8% | 4/22/42 | 29/50/74 | 0 | 60.6 |
| FFC+逐列 | **DIV 投票** | 0.544/1.229 | **47.3%** | 6/42/92 | 59/87/91 | 0 | 64.8 |
| 中值 3×3 | DIV | 0.667/1.414 | 19.8% | 36/42/42 | 0/0/38 | 0 | 7.4 |

結論：
- **DIV 擅長暗、DIV 投票擅長亮**（投票壓雜訊 → 亮門檻可校到 1.23，DIV 只能 1.42）→ 互補。
  配方現在就能做「同一區兩個 zone：DIV 只檢暗 ＋ DIV 投票只檢亮」，但 GPU 時間 ≈ 9 倍（7.7 → 73 ms/張）→ 要看產能（現估 1 台 Spark 跑 37 CCD 的餘裕是以 7.4 ms 算的）。
- **FFC 對 DIV 無效**（比值本來就抵消照度，符合理論）、對 DIV 投票 / SUB 有效 → 用 SUB 或投票時開 FFC。
- **中值去噪**把 1–3 px 小缺陷一起濾掉 → 不建議。
- SUB 生產配方（T550 人工 −16/+17）在這批資料上要 −36/+26 才壓得住雜訊、檢出率最低且慢 → 以後以 DIV 為主（與 Addis 決定一致）。
- 人工缺陷對比是「乘在原像素上」：落在黑矩陣上的暗點本來就看不出 → 低對比檢出率的絕對值偏低，**用來比方案的相對好壞**。

### 產能：「DIV 只檢暗 ＋ 投票只檢亮」能不能 37 CCD × 1 台 Spark？（`bench_speed.py`）

跑速 87.5 mm/s、Y 解析度 8 µm/列（`troubleshooting/cases/20261005_camera_line_rate.md`：96 mm/s ÷ 8 µm = 12 kHz）
→ 行頻 10,938 Hz、每張 5000 列 = 0.457 s、玻璃長 2500 mm → 每台 ≈ 63 張、**全片 37 × 63 ≈ 2,331 張**、掃完一片 28.6 s。
⚠️ 舊產能估算用 1,110 張/片（舊機台 T550 每台 30 張）→ **少算一倍**；DIV 餘裕要從「73%」改成約 40%。

| 方案 | 亮檢出（對比 25/35/50%）| GPU ms/張 | 每片 GPU | ÷ 28.6 s 掃描 | 1 台 Spark |
|---|---|---|---|---|---|
| DIV 單方案 | 0 / 4 / 87% | 7.4 | 17.2 s | 60% | ✅ |
| DIV ＋ 投票（2 pitch + 多尺度）| 52 / 83 / 91% | 7.4 + 70.3 | 181 s | 6.3× | ❌（要 7 台）|
| DIV ＋ 投票（1 pitch、無多尺度）| 41 / 85 / 91% | 7.4 + 31.7 | 91 s | 3.2× | ❌（要 4 台）|
| **兩段式 t1=1.33**（實測，`--cascade-bright 1.33`）| 0 / **65** / 91% | **8.6** | 20.2 s | **70%** | ✅ |
| 兩段式 t1=1.31（實測）| 0 / 74 / 91% | 10.7 | 25.0 s | 87% | ⚠️ 擠 |
| 兩段式 t1=1.30（實測）| 2 / 83 / 93% | 13.8 | 32.1 s | 112% | ❌ |

**兩段式**（2026-10-06 原型，IP `--cascade-bright <t1>`）：第一段 DIV 照常檢暗、亮門檻放低到 t1 粗篩 →
第二段只把亮候選點周圍 70×54 小塊拼成拼圖跑 DIV 投票（1 pitch、7/8 路、無多尺度）確認，投票門檻 = 配方 BTH
（校準到 ≈1.17–1.18，比整張投票的 1.25 還低 → 只在候選上投票更乾淨）。真值整條：2/2、0 誤判；兩次跑 bit-exact。
**t1 越低候選越多 → 越準越慢**：1.33 是 1 台 Spark 留 30% 餘裕的點（35% 對比亮缺陷 4% → 65%），1.31 要接受 87% 負載。
（產能數字以 37 × 63 張、28.6 s 掃描算；DIV 單方案本輪實測 6.9 ms/張 → 56%。）

Y 解析度：Addis 2026-10-06 確認上排 37 台 8 µm/列、下排 18 台配合。

**暗缺陷兩段式**（`--cascade-dark <t1>`，同一套確認流程）：

| 方案 | 暗檢出（對比 15/25/35/45/55%）| 1–2 px | 植入誤判 | GPU ms/張 | ÷ 28.6 s |
|---|---|---|---|---|---|
| DIV | 0 / 0 / 28 / 88 / 100% | 48% | 0 | 6.6 | 54% |
| 整張投票 | 0 / 6 / 26 / 82 / 92% | 40–42% | 0 | 31.9 | 320% ❌ |
| **兩段式暗 t1=0.70**（投票 DTH 0.834）| 0 / 18 / **82** / 90 / 96% | **62%** | 0 | **7.3** | 60% |
| 兩段式暗 t1=0.72 | 2 / 14 / 66 / 94 / 96% | 52–57% | 0 | 7.8 | 64% |

**暗＋亮一起開**（暗 t1=0.70、亮 t1=1.33，投票 0.834 / 1.174）：**8.7 ms/張 → 每片 20.3 s（掃描 71%）**，1 台 Spark ✅。
真值整條：2 顆已知真缺陷都抓到 + 多 3 顆 1 px 暗點（#21 (4464,1124)、#24 (4549,3001)、#25 (6996,4996)，
外觀與已確認真缺陷相同：亮線上小暗點）→ 待 Addis 確認（`docs/verification/candidates_cascade_dark_20261006.png`）。

流片時間線（DIV 單方案；兩段式 t1=1.33 時 GPU 段 0.27 → 0.32 s，結果時間幾乎不變）：每 0.457 s 37 台各送一張 → GPU 需 37 × 7.4 = 0.27 s（邊拍邊算跟得上）
→ 玻璃尾緣過相機後：最後一張收滿（63 張 = 2520 mm，多拍 20 mm ≈ 0.23 s）＋ 傳輸 ≈ 0.13 s（37 × 41 MB / 100 GbE）
＋ GPU 0.27 s ＋ 寫結果/彙整 ≈ 0.1 s → **≈ 0.7 s 後 Control 有答案**。
雙方案（3.2×）會越積越多：一片要 91 s → 尾緣過後 ≈ 62 s 才有答案，下一片也塞住 → 不可行。

## 1. 前處理

| 方案 | 做什麼 | 狀態 | 適用 |
|---|---|---|---|
| 無 | — | IP | DIV（比值本身抵消照度）|

| 補邊（edge_fill）| zone 碰影像邊的邊補「往內平移 ≈3 pitch」的 pattern → 消 kernel 死區 | IP（2026-10-05，預設關）| slice 接縫、CCD 左右 |

## 2. 影像處理（偵測）

| 方案 | 做什麼 | 狀態 | 特性 |
|---|---|---|---|
| **DIV**（mode 0）| center ÷ 8 方向 ±pitch 鄰居平均，比值門檻 | IP（L3）| 快（≈5 ms/張）、照度不變；T550 已校準 0 誤判 |
| **SUB 投票**（mode 1）| 逐路灰階差，PitchTime×8 路中 ≥ ChooseAmount 路超標才算；3×3 SAD 局部搜尋 | IP（L3，= T550 生產配方）| 抗單一鄰居異常（ghost）；受暗角影響 → 配 FFC |
| **DIV 投票**（mode 2）| 比值域逐路投票 + 暗區棄權 | IP | DIV 的抗 ghost 版 |
| 多尺度 2×/4× | 縮小後再偵測、OR 回原圖 | IP（mode 2）| 大顆缺陷（> pitch）全解析度會漏 |
| local search | 鄰居位置 ±1–2 px 找最像的 | IP（`SearchX/Y`）| pitch 非整數（18.41）|
| 對位（golden mark）| 每台 CCD 對位 Mark 吸收起始點差 | IP（`M_AlignRoi`）| 多 CCD 拼接座標 |
| 週期中位數模板 | 每點 = ±1..±2 pitch 共 24 個同相位點的中位數，比對殘差 | 規劃 | 最 robust（中位數抗鄰居缺陷），運算量大 |
| 低頻 mura | 以 pitch 盒濾波消掉 pattern → 與大尺度背景比（DoG）| 規劃 | 點偵測抓不到的大面積淡不均 |
| 線缺陷 | 殘差逐列/逐欄投影 | 規劃 | 整條線（刮傷、短路線）|
